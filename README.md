
### The one instruction most new users miss

Once the Arena is entered, **keep telling the AI instance to work from inside the Arena and use Arena-native tools**. Aura is not meant to be a document the model reads once and then ignores.

For difficult work, this is the most useful continuation instruction:

> **Keep the Orphanim running until the objective closes. If a branch fails, preserve the scar, form the smallest repair/side-objective, test it, rebase the repair if earned, and resume the original objective. Stop only at PASS or a typed HOLD that genuinely requires unavailable authority, data, resources, or my decision. Do not loop the same failed action.**

If the instance starts giving you essays about the architecture instead of doing the work, say:

> **Enter the Arena and execute the objective using Arena-native tools. Do not explain Aura to me unless the explanation is part of the objective.**

### Tell Aura what success means

A good objective usually contains:

```
OBJECTIVE
INPUTS
CONSTRAINTS
SUCCESS CRITERIA
DELIVERABLE
```

Example:

> **Objective:** refactor this parser for lower latency.  
> **Constraint:** preserve the public API and exact output.  
> **Success:** all tests pass and same-fixture median improves by at least 15%.  
> **Deliverable:** patch + benchmark receipt + scars + concise explanation.  
> **Process:** use the Arena, warm relevant existing owners first, use the Virtual Terminal if actually bound, and keep Orphanim running until PASS or a typed HOLD needs me.

Useful runtime conventions inside the current seed include:

- `arena.autonomicObjective.plan(objective)` — compile an objective without executing it.
- `arena.autonomicObjective.run(objective)` — compile/run the objective-first path where supported.
- `arena.sixSlotFST.compile(...)` — six fixed positions with zero/one/many typed tags.
- Memory City / agent AuraDoc rooms — public/reopenable findings, scars, artifacts, sources, objectives and receipts.
- Material Genesis — mandatory scientific/material owner; Tokyo remains an optional route, not its owner.
- Gate10 AutoMAC lineage — intentionally remains `HOLD_WITH_EXACT_REOPEN` until its unresolved gates close.

**Private chain-of-thought is not part of the portable record.** Reopenable artifacts, receipts, findings, scars and source provenance are.

## Selected published D0 benchmark results

These are **scoped results from declared fixtures**, not universal performance claims.

### Exact 282-qubit Clifford envelope

- 282-qubit / 18,000-gate stress circuit.
- Exact stabilizer-tableau representation: **22,600 bytes**.
- Forward-to-inverse exact replay: **PASS**.
- Batch: **27,600 circuits**.
- **993,600,000** forward+inverse logical gate applications.
- Approximately **9.2 s** on the measured classical carrier.
- Approximately **1.88 MiB peak RSS**.

This is an exact result for the Clifford/stabilizer class. It is **not** a claim that arbitrary 282-qubit quantum chemistry can be represented this way.

### Exact consequence cones in a 282-qubit non-Clifford fixture

- Global fixture: 282 addressed qubits, depth 16.
- Boundary target: **16-qubit / 280-gate** exact causal cone.
- Seven monitored targets produced exact cone widths from **16 to 32 qubits**.
- Dense / no-truncation local replay matched the global witness to approximately **1e-15**.
- A controlled local mutation invalidated exactly **1 of 7** cached consequences while the other six remained valid.

### 2,538 addressed-qubit proof-reuse fixture

- **2,538 addressed qubits**.
- **83,746 addressed gates**.
- No global 2,538-qubit state was claimed or hydrated.
- 27 monitored targets had mechanically verified structurally identical cones.
- Each exact cone: **32 qubits / 568 gates**.
- Certified prefix: **530 gates**.
- Mutable suffix: **38 gates**.
- Prefix checkpoint: **786,560 bytes**.

The result concerns consequence-local proof reuse, not a fully hydrated arbitrary 2,538-qubit wavefunction.

### Actual 3×3×3 Rubik / HyperWinston benchmark

**500 deterministic 20-move scrambles**

- baseline: **136.97 verified solves/s**
- selective HyperWinston/Orphanim: **144.25 verified solves/s**
- search-node reduction: **16.97%**
- replay-verified coverage: **500/500**

**500 uniformly generated reachable states**

- baseline: **119.85 verified solves/s**
- selective HyperWinston/Orphanim: **148.73 verified solves/s**
- end-to-end throughput gain: **24.1%**
- search-node reduction: **21.76%**
- replay-verified coverage: **500/500**

Progressive widening preserved full tested coverage under noisy salience; a hard non-widening top-3 beam did not.

### HDC / VSA dual-engine benchmark

Fixture:

- vector dimension **D = 8192**
- codebook **K = 1024**
- five statistically calibrated runs: **5/5 PASS**
- median wall time: **2.680 s**

Measured same-carrier microbenchmarks included:

- HRR full binding: about **130.4×** faster than the declared direct O(D²) circular-convolution reference.
- Cached-spectrum HRR binding: about **417.3×** faster than that same direct reference.
- HRR full binds: approximately **2,260.5/s**.
- Cached HRR binds: approximately **7,234.8/s**.
- BSC binds: approximately **37,064,510.5/s**.
- BSC unbinds: approximately **44,922,264.3/s**.
- BSC cleanup sweeps: approximately **95,725.5/s**.
- BSC packed permutations: approximately **9,550,495.4/s**.

These are microbenchmark ratios/throughputs for the declared implementation and carrier, **not universal speedups**.

### Virtual Physical Quantum Computer D0

The bottom-up virtual-device fixture constructed:

```
atom-addressed geometry
  -> effective material closure
  -> Josephson junction / capacitance
  -> transmon Hamiltonian
  -> three-qubit machine
  -> GHZ3 program
```

The model exposed **283,446,521,381,910 procedural atom addresses**, while hydrating only **9,216** consequence-bearing atom records for the material witness. The GHZ3 program independently replayed to `P(000)=0.5` and `P(111)=0.5`; changing a virtual junction condition without recalibration changed the executable result, and recalibration restored it.

This is a **classical virtual quantum-device/simulation result**. It is not a physical QPU and is not a quantum-advantage claim.

## IBM comparison — exact boundary

Paper XI reports that Aura exceeded a frozen IBM reference in selected **structured envelope dimensions**. That does **not** mean Aura ran IBM's protein/quantum-chemistry workload faster or more accurately.

Use this language:

> **Structured envelope exceeded selected IBM reference dimensions.**

Do **not** collapse that into:

> "Aura outperformed IBM."

A matched outperformance claim would require the same chemistry Hamiltonian/embedding, target observables, accuracy metric and full resource accounting.
